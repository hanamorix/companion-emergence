# 1.5-criteria.md — Cascade Compaction

**Conformance oracle for stage 8.** Each criterion is checkable (automated true/false or numeric). Default
**gating**; advisory only with a stated reason. **Measurement posture:** the project has **no replay/held
workload** (config `metrics` are advisory-only across the board today — no live bridge), so all *regression*
metrics are advisory; "done" rests on the **conformance** criteria below, verified by execution on scratch
fixtures. (`decisions.md` records this posture at gate 4.)

**Two mandatory-lens criteria fire for this change:**
- **Position lens (ST1.5d):** the head prefix is a position-sensitive assembly (`engine` authors it,
  `budget` re-parses it by prefix). → **C6** (behavior-preservation, verified by execution).
- **Concurrency lens (ST1.5e):** the change adds writers/read-modify-write windows over the shared session
  buffer + archive + successor pointer (cascade pass, rollover extract→archive→delete→seed, finalize-tick
  change, archive segment writer, `rolled_to.json`). → **C10** (finalize↔rollover no-lost-update), **C11**
  (archive crash-durability), **C15** (old-buffer reaping / active-set boundedness), **C16** (successor
  redirect at the real `get_or_hydrate_session` locus, the 4 operation handlers), **C17** (atomic 3-tier cascade write),
  **C19** (`in_flight_locks` keyed by resolved sid), **C20** (close-path cleanup keyed by resolved sid — no
  successor leak) — each verified by an *injected* interleaving or crash simulation that fails against the
  unguarded/pre-change version.

Each criterion names an **oracle shown able to fail** (ST1.5f): run it against the pre-change / known-bad
state and confirm it flags the violation, before a PASS counts.

## Gating criteria

### C1 — Three-section representation (one row)
After a cascade pass over material spanning >72h, the `summary` row holds **exactly three age-labelled
sections** (24h / 48h / 72h) in **one** row (not three rows).
- **Oracle:** parse the stored summary row; assert 3 labelled sections + single-row invariant.
- **Fail-demo:** run against pre-change single-layer output → oracle flags "missing 48h/72h sections".

### C2 — Cascade wiring: AGE-GATED, oldest-first, correct sources
On a fixture with turns at known ages, one cascade pass buckets material by **actual age**: raw turns are
age-partitioned (`G24=(24h,48h]`, `G48=(48h,72h]`, `G72=(>72h]`); each existing section is age-classified by
its newest covered ts and merges down if aged out; then, oldest-first, 72h ← recompact([secs@72h]+G72),
48h ← recompact([secs@48h]+G48), 24h ← fold([secs@24h]+G24). One code path, one lock; the pass reads all
pre-pass inputs before writing (no section reads an already-rewritten tier).
- **Oracle:** instrument the pass to record, per tier, `(age_bucket, source_sections, raw_group, order)`;
  assert each tier's inputs are exactly the material whose age falls in that tier's bucket, and order==[72,48,24].
- **Fail-demo:** a tick-count-shift or youngest-first scratch → oracle flags a tier fed by wrong-age material.
- (Layer↔age correspondence under skipped ticks is the distinct behavior C14 governs.)

### C3 — Tier hard caps bound the head (tier1 + terminal tier3)
Tier 1 folds to ≤ `_SECTION_24H_CHAR_CAP`; **terminal tier 3**, re-compacted every cycle, folds to
≤ `_SECTION_72H_CHAR_CAP` (= 0.20 × tier1 cap) even after many cycles (OWNER 2026-08-13). Tier 2 is
bounded-by-input (no separate hard cap).
- **Oracle:** feed an over-cap batch and run **many steady-state cycles** (tier3 folds 2 inputs/cycle);
  assert `len(tier1) ≤ _SECTION_24H_CHAR_CAP` AND `len(tier3) ≤ _SECTION_72H_CHAR_CAP` across cycles.
- **Fail-demo:** remove either cap → oracle flags length > cap (terminal tier3 grows unbounded as the
  persisting section + each graduated tier2 accrete without the cap).
- (60%/40%/20% are the soft targets; the tier1 and tier3 caps are absolute bounds — see plan §Q8.)

### C4 — Fold-output validation (#77), incl. the CASCADE double-reject fallback
A fold/re-compaction output that is a refusal / non-first-person / "I won't proceed"-style completion is
**rejected**, retried once, and on repeat failure the **source material is preserved, never dropped, never
stored via bare `.strip()`**. Under the cascade, a double-rejected section build (e.g. 48h ← [24h]+G48) must
NOT silently discard its input material (stage-3 L3): the target falls back to a lossless-leaning safe join of
its inputs (truncated at a sentence boundary to the tier's bound), recorded as a soft-fail.
- **Oracle (drives the real `cascade_conversation` path, not only the `_validate_fold_output` unit):**
  (a) single-fold: inject a known-bad output; assert not-stored + one retry + prior value unchanged on repeat.
  (b) cascade: inject a double-reject on the 48h build; assert the 24h input material is carried into the
  section (present), not lost.
- **Fail-demo:** disable the validator → garbage stored; use a "drop-on-double-reject" scratch → (b) flags the
  24h material missing.

### C5 — Temporal markers (#82) + owner age-band labels
Each section header carries (a) a coarse wall-clock anchor derived from the covered turns' `ts` (a date/time
span, not per-sentence stamps) AND (b) the **owner-specified human label**: tier1="yesterday",
tier2="day before yesterday", tier3="a few days ago" (OWNER 2026-08-13).
- **Oracle:** fold turns with known `ts`; assert the header contains a coarse span matching those ts AND the
  correct human label per tier.
- **Fail-demo:** strip ts at fold input → missing/empty span; use bare "24h/48h/72h" labels → oracle flags the
  wrong label.

### C6 — Cache-stable head prefix (POSITION-SENSITIVE; behavior-preservation, verified by execution — ST1.5d/H3)
The behavior that depended on the arrangement — `budget.py` recovering the head by prefix-parse, and the head
staying byte-stable between daily re-compactions — is preserved for the 3-section render.
- **Oracle (executed, not inspected):**
  (a) render the head from a fixed 3-section summary **twice with no re-compaction between**; assert the two
      renders are **byte-identical** (byte-stable between re-compactions);
  (b) feed the rendered head to `budget.py`'s re-parse; assert it recovers the head region correctly
      (authoring ↔ re-parse in lockstep).
- **Fail-demo:** inject a per-render nonce/live-timestamp into the render → (a) flags a byte diff; break the
  prefix token → (b) flags a re-parse miss. Verified by **running** the render+parse, never by re-reading the
  assembled text (H3).

### C7 — Lossless-before-lossy + cursor guard + idempotent (invariants preserved)
The pass never compacts an un-extracted turn (cursor guard), archives + **byte-count-verifies** before
rewrite, and is idempotent (a second pass on stable input is a no-op).
- **Oracle:** (a) fixture with an un-extracted tail → assert it is not folded; (b) assert archive byte-count
  verify runs before the buffer rewrite; (c) run the pass twice → assert second run makes no change.
- **Fail-demo:** remove the cursor guard in a scratch copy → (a) flags an un-extracted turn folded.

### C8 — 1c-A: >24h stale-resume rollover (SYNC) + stale selection
On a stale resume (last turn age > `_ATTACH_MAX_AGE_HOURS`), `/sessions/active` returns a **new session id
(not null)**; the old conversation is fully folded (`min_keep_tail=0`) + archived + **the old buffer deleted**;
the new session's **first head row is the seed summary**, marked already-extracted; the resume is **blocked
until the seed is written** (SYNC — owner-ratified). When **multiple stale buffers exist**, the
**most-recently-active** (max last-turn ts) is the one rolled over/seeded (stage-3 A1-b).
- **Oracle (drives the REAL `/sessions/active` endpoint via FastAPI TestClient + the real rollover fn, not a
  bespoke helper):** (a) single stale fixture → non-null new sid, archived + deleted old buffer, seed head
  flagged extracted, write completes before return; (b) multi-stale fixture → assert the most-recently-active
  was selected.
- **Fail-demo:** pre-change handler → `null` / no seed; a "pick-arbitrary" scratch → (b) flags wrong selection.

### C9 — 1c-B: weekly-cap rollover driven from the DAILY TICK at a quiet moment
When session age ≥ `_WEEKLY_ROLLOVER_AGE`, the rollover fires **from the daily supervisor tick** (NOT only at
attach — the continuous client is the target population), at a **quiet moment** (last turn older than
`_ROLLOVER_QUIET_GAP`, never mid-exchange), seeding a new session with **the 3 compaction tiers + the 40
most-recent messages**, old buffer archived + deleted.
- **Oracle (drives the REAL daily-tick fn `_run_compaction_tick`, not a bespoke helper):** fixture with
  session age ≥ cap and last turn older than the quiet gap → assert (a) the daily tick fires the swap;
  (b) new session seeded with 3 tiers + 40 messages; (c) old buffer archived + deleted; (d) a fixture with a
  recent last turn (within the quiet gap) → the swap defers (no mid-exchange fire).
- **Fail-demo:** attach-only scratch (never re-attaching client) → weekly cap never fires; "fire immediately"
  scratch → (d) flags a mid-exchange rollover.

### C10 — Finalize decoupling: no-lost-update over the session buffer (CONCURRENCY; injected interleaving — ST1.5e/H4)
The finalize tick **no longer deletes conversation buffers** (rollover owns that lifecycle); it still runs
memory extraction. **Accessors of the session buffer** must be enumerated (plan §5); a rollover seed-write
must **survive** a finalize tick interleaved into its read→write window.
- **Oracle (injected interleaving):** drive a rollover seed-write; inject a finalize tick into the middle of
  its window; assert the seed survives (not deleted), finalize did **not** delete, and memory extraction ran.
- **Fail-demo:** the test must **fail against the pre-change finalize tick** (which deletes the buffer) —
  proving the decoupling is what saves the write, not luck.
- (Old-buffer *reaping* correctness — that the superseded buffer IS deleted by the rollover path and the
  active set stays bounded — is the distinct behavior C15 governs.)

### C11 — 1d: archive segmentation + multi-segment reader + atomicity (CONCURRENCY-atomicity)
A long archive is written as **multiple rolling segments**; the **segment-aware reader** (extending the
existing whole-file `read_archive`, `buffer.py:310`) reconstructs the full sequence in order with the
**provenance chain intact**; the **archive-before-rewrite byte-count atomicity** contract is preserved; a
**crash mid-roll** (an unsynced/created-but-empty new segment, or a torn final line) still reads back the full
prior chain; a **non-segmented (legacy) archive still reads** (back-compat). (Append-during-roll is
lock-precluded per plan §5, so the oracle targets the crash case, not a concurrent-append interleaving —
stage-3 C11 re-point.)
- **Oracle:** append past the segment threshold → assert (a) >1 segment file; (b) reader returns the exact
  original sequence, numeric-ordered; (c) provenance fields intact; (d) byte-count verify still gates the
  rewrite; (e) **simulate a crash mid-roll** (created-but-unsynced segment / torn trailing line) → reader
  still returns the complete prior provenance chain. New-segment creation **fsyncs the containing directory**.
- **Fail-demo:** point the reader at only the newest segment → flags missing earlier records; disable
  byte-verify → (d) flags; skip the directory fsync + torn-line tolerance → (e) flags a lost tail.

### C12 — Migration: single-layer → sectioned as TIER 3 (old-floor), idempotent, #82-safe (round-6 MO-1 / round-7 MO-2)
A persona whose store holds a legacy single-layer summary (accumulated history) migrates once to the sectioned
form seeded as **tier 3 ("a few days ago"), NOT tier 1**, with `covers_from_ts` set to an explicit **old-floor**
(`migration_now − 96h`, `_LEGACY_AGE_FLOOR`) **unconditionally — never `covers_until_ts`**; re-running the
migration is a **no-op**.
- **Oracle:** (a) legacy-form fixture (months-old history) → post-migration content is in tier 3, and running
  the cascade on the migrated output → **stays tier 3, NOT tier 1**; (b) **the fallback branch** — a legacy
  blob with **no derivable oldest ts** → assert tier 3 AND **survives the NEXT cascade pass still tier 3** (the
  classifier keys on the old-floor `covers_from_ts`, not a recent value); (c) **delayed-backlog interaction
  (round-8)** — a persona already sections-migrated, THEN hit by a delayed `run_backlog_migration` retry that
  flattens the row to single-layer → the tolerant reader + next cascade re-establish it as **tier 3, not
  tier 1**; run migration again → no change.
- **Fail-demo:** the "legacy → tier1" OR "fall back to `covers_until_ts`" mapping → the cascade labels
  months-old history "yesterday" on the next pass (reproduces #82). (This is the load-bearing MO-2 assertion.)

### C13 — Interior-continuity read not starved
After a cascade pass, the `monologue_trace` read path (`ambient.py`) still returns its content — the cascade
does not remove/starve that read.
- **Oracle:** seed `monologue_trace`; run a cascade pass; assert `ambient.py`'s read still returns it.
- **Fail-demo:** null the trace store in a scratch copy → oracle flags empty read.

### C14 — Graduation + TERMINAL tier-3 persistence + layer↔age under gaps (F1/L1 + F3 + OWNER 2026-08-13)
Three properties, one criterion: **(graduation, F3)** under **continuous daily use**, each cohort migrates
tier1→tier2→tier3 by true content age — material sown day 0 is in tier1 after 1 pass, tier2 after 2, tier3
after 3; **(terminal, OWNER)** it then **PERSISTS in tier3 (fading) on passes 4, 5, …** — NOT gone/archived
(tier 3 is terminal-with-fade; there is no 4th tier and no evict leg); **(gap robustness, F1)** after a
skipped/multi-day-gap tick, material lands in the tier its **actual age** dictates, and after **long
inactivity only tier 3 is populated** (tiers 1 & 2 empty). Asserted against **actual source-content age**
(a marker), NOT `covers_until_ts` (the classifier's own input → tautological).
- **Oracle:** a **fake provider that preserves markers** (identity/concatenative fold); sow identifiable turns
  on **consecutive** days; run many consecutive daily passes; assert each marker's tier by pass number
  (1→tier1, 2→tier2, 3→tier3, **4,5,…→still tier3**). **Multi-input (F1):** assert that in a steady-state
  cycle the new tier3 contains markers from **BOTH** the persisting prior tier3 **and** the newly-graduated
  prior tier2 (neither input dropped), within `_SECTION_72H_CHAR_CAP`. Separately: a long-inactivity fixture →
  only tier3 populated; a multi-day-gap sequence → markers land by true age.
- **Fail-demo:** (a) newest-edge-classify + prior-tier1-remerge → marker never leaves tier1 (F3); (b) a
  "72h→evict" scratch → marker wrongly gone after pass 4 (violates terminal); (c) a single-input tier3 fold
  that keeps only one of the two inputs → the other input's marker missing (violates multi-input F1); (d)
  tick-count-shift → material mislabelled after a gap (F1).

### C15 — Active-set boundedness: old buffer reaped by the rollover path (stage-3 CH8-2, L2)
A rolled-over old session's **buffer is deleted** by the rollover path (not left behind), so
`list_active_sessions` does not accumulate rolled-over sessions across ticks; finalize never deletes (C10) but
rollover does.
- **Oracle:** roll over a session (either trigger); assert the old buffer file is gone and the active-session
  set does not include it on the next tick; drive N rollovers → active-set size stays bounded (not O(sessions
  ever created)).
- **Fail-demo:** the "finalize delete removed but unassigned" draft → oracle flags the old buffer persisting /
  the active set growing.

### C16 — Post-rollover continuation redirects at the REAL locus, the four OPERATION handlers (P-1 + F1; /state read covered by C20/C21)
After a weekly swap, a client still holding the **old** sid is transparently redirected to the **current
successor** — verified at the **real resolution chokepoint** (`get_or_hydrate_session`, `session.py:129-205`,
consults `rolled_to.json` and **full-follows the chain to its end**, L-1), not a proxy. The four operation
handlers (`/chat` :2365, `/stream` :2424, `/sessions/snapshot` :2696, `/sessions/close` :2753) each use the
**resolved** `sess.session_id` for their backend call, or close/snapshot silently no-op on the deleted old
buffer and falsely report success (round-3 F1). The round-1 oracle (a bare `ingest_turn(old_sid)` unit call)
was a proxy and is disqualified.
- **Oracle (real paths):** perform a weekly swap (old buffer deleted + evicted + `rolled_to.json` written);
  (a) `get_or_hydrate_session(old_sid)` → returns a `SessionState` with `session_id == successor_sid`;
  (b) via FastAPI **TestClient** with `session_id=old_sid`: `POST /chat` → **200** + turn in the **successor**
  buffer; **`POST /sessions/close` + `POST /sessions/snapshot` → operate on the successor**, NOT a
  `committed=0` false-success no-op.
- **Multi-generation (L-1):** perform **three** successive rollovers sid1→sid2→sid3; a client still holding
  **sid1** → `get_or_hydrate_session(sid1)` resolves to **sid3** (full chain follow), and `POST /chat` with
  sid1 → 200 + turn in sid3's buffer. A **cyclic** pointer (corrupt) → aborts to 404 (visited-set guard), not
  a hang.
- **Fail-demo:** redirect removed → (a) None / (b) 404; single-hop-only follow → multi-generation resolves to
  sid2 not sid3; close/snapshot passing raw `req.session_id` → (b) silent no-op. The bare `ingest_turn` call
  is NOT the oracle.

### C19 — `in_flight_locks` keyed by the resolved sid (stage-3 round-3 F2)
All `get_or_hydrate_session` handlers key/read `in_flight_locks` (`server.py:816`) by the **resolved
`sess.session_id`**, so traffic on the old sid (redirected) and traffic a second client sends on the successor
sid serialise on the **same** lock key — no two-key concurrent write to one buffer.
- **Oracle:** after a swap, drive traffic on both the old sid and the successor sid; assert both acquire the
  same `in_flight_locks` key (the resolved successor sid) and cannot run concurrently.
- **Fail-demo:** key by raw `req.session_id` → two distinct keys → the oracle observes concurrent access to
  one buffer.

### C20 — Close cleanup + /state use the resolved sid — no successor leak/misreport (round-4 G1 + round-5)
`/sessions/close` cleanup (`remove_session` + `in_flight_locks.pop`, `server.py:2835-2836`) and `/state`'s
in-flight lookup (`server.py:1265`) use the **resolved `sess.session_id`**, so closing/querying on the old sid
acts on the **successor** — not the gone old id.
- **Oracle:** after a swap, `POST /sessions/close` with the **old** sid (TestClient) → assert the successor's
  `_SESSIONS` entry removed + `in_flight_locks` key popped; and `GET /state` on the old sid reports the
  successor's in-flight state correctly (not a stale/false value).
- **Fail-demo:** cleanup/state keyed by raw `req.session_id`/path `session_id` → successor left live + lock
  leaked; `/state` misreports in-flight.

### C21 — Structural guard: no raw sid downstream of resolution — the redirect class stays closed (round-5 F2)
For **every** handler in `server.py` that calls `get_or_hydrate_session`, no raw request/path `session_id` is
used downstream for a load-bearing op (backend pipeline call, `in_flight_locks` key, `remove_session`,
`/state` in-flight, echoed id) — the resolved `sess.session_id` must be. This is a **static/structural** check
(not a runtime probe) so a **future 6th caller** cannot silently regress the class.
- **Oracle:** parse/scan each `get_or_hydrate_session` handler body; assert the downstream load-bearing ops
  reference the resolved binding, not the raw id. (Shown able to fail: run against the pre-fix tree where all
  5 sites use the raw id → the check flags each.)
- **Fail-demo:** the current (pre-sweep) code → the check fires on every unfixed site.

### C22 — apply_budget backstop operates correctly on the sectioned row (round-5 F3 minor)
The `apply_budget` 24h-only emergency backstop reads/updates the **sectioned** summary row without corrupting
sections and without running the full age-gated re-bucket; the head stays re-parseable (C6).
- **Oracle:** drive the real `apply_budget` against a sectioned row; assert the 24h section is bounded, other
  tiers untouched, sections intact, head re-parses.
- **Fail-demo:** a scratch backstop assuming a flat single-layer row → mis-parses/overwrites sections.

### C17 — Cascade write is atomic across the three tiers (stage-3 round-2 minor)
All three tiers are computed from the pre-pass snapshot and installed in **one** `rewrite_session_atomic`
(`buffer.py:265`), so a crash cannot leave a half-updated row (e.g. a new 72h beside an old 24h).
- **Oracle:** run a cascade pass with an injected failure **before** the atomic replace; assert the on-disk
  summary row is still the **pre-pass** row (no partial tier update), and the archive-before-rewrite
  byte-count verify gated the write.
- **Fail-demo:** a 3-sequential-archive+rewrite scratch → oracle flags a partial row after a mid-sequence
  failure.

### C18 — Carried raw-tail extraction state preserved across rollover (re-pointed per stage-3 round-6 UA-2)
The seed **summary** row cannot be re-extracted regardless of cursor — `pipeline.py`'s speaker-filter blocks a
`speaker=="summary"` row unconditionally, so a "seed cursor prevents re-extraction of the seed" criterion
tests a guarantee that already holds. The **real** cursor-dependent risk is **1c-B's carried 40-message RAW
tail** (`min_keep_tail=40`): those raw messages ARE extractable, so the new session's cursor must carry the
old session's extraction state so that **already-extracted** carried messages are NOT re-extracted (no
duplicate memory) while **not-yet-extracted** carried messages still get extracted.
- **Oracle:** after a 1c-B rollover, seed the new session with a 40-msg raw tail whose old-session extraction
  state is mixed (some extracted, some not); run the new session's extraction; assert already-extracted
  carried messages are **not** re-extracted (no dup memory) and unextracted ones **are** extracted.
- **Fail-demo:** seed without carrying the cursor/extraction state → oracle flags duplicate memories from the
  already-extracted carried tail (or lost extraction of the unextracted tail).

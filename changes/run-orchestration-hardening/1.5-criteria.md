# 1.5 — Acceptance criteria: run-orchestration hardening

Labeled **gating** (must pass to ship) or **advisory**. The anti-stall guarantee is
**structural/contractual, not behavioral-test-enforced** — see the note at the end and
`8-harness.md`. Criteria prove the mechanical facts only.

## Gating

**G1 — The blocking helper blocks and returns in-turn (populated result), via the REAL path.**
A unit test drives `boot_and_verify(...)` with a `boot_cmd` that writes a valid `READY` file
(and no `ERROR`) into the run dir — the real boot+confirm path. It returns a populated
`ArmSession` (parsed READY payload) synchronously — the call returns to the test, spawns
nothing backgrounded, and does not block indefinitely. No injected verify fakes: the READY
confirmation logic that runs is the real shipped logic. Verified in
`tests/unit/harness/test_foreground.py`.

**G2 — A dead/failed boot raises in-turn, does not hang.**
A unit test drives `boot_and_verify(...)` with (a) a `boot_cmd` that exits non-zero, (b) a
`boot_cmd` that writes an `ERROR` marker instead of `READY`, and (c) no READY appearing within
a short bounded `ready_timeout`. Each raises `ForegroundBootError` synchronously within the
bounded timeout — it does NOT hang. The test asserts the raise happens and the call completes
quickly (well under the suite's own timeout). Verified in `test_foreground.py`.

**G3 — The real verification paths reject a bad build in-turn.**
Real-path (no fakes), two arms: (a) `boot_and_verify(...)` given an `expect_brain_repo_under`
and a `READY` payload whose `brain_repo` is NOT under it raises `ForegroundBootError`
synchronously; (b) `assert_tool_callable(source, "read_full_memory")` over a crafted
turn_diag/transcript whose served MCP roster does NOT contain the tool (simulating a silently
tool-less MCP child) raises `ToolSideBroken`, while a transcript that DOES contain it returns
cleanly. These exercise the actual governed logic (READY payload parsing; served-roster
scanning), not an injected proxy. Verified in `test_foreground.py`.

**G4 — `preserve_artifacts` copies the raw artifacts, returns paths, and raises on a missing REQUIRED source.**
A unit test creates a fake run dir containing `turn_diag.jsonl`, `transcript.jsonl`, and a
subprocess-transcript dir with a file, calls `preserve_artifacts(run_dir)`, and asserts the
files/dir are copied into the preserve dir and the returned `PreserveResult` lists them. A
second arm asserts that a source named in `require=(...)` that is absent raises
`PreservationIncomplete` (NOT a silently-green result), while a non-required missing source is
reported in `PreserveResult.missing` and does not abort preserving the others. Verified in
`test_foreground.py`.

**G5 — The banner function emits the exact required text.**
`drive_now_banner(...)` returns a string whose first line is exactly
`▶ DRIVE NOW, IN THIS SAME TURN — do not end your turn to wait`
(verbatim, including the em-dash and the ▶). The returned string also names both parkable
surfaces (background Bash task AND background sub-agent) and restates the one rule. A unit
test asserts the exact first line by equality and asserts both surfaces + the rule appear.
Verified in `test_foreground.py`.

**G6 — The contract doc ships in `tests/harness/` and names both surfaces + the one rule.**
`tests/harness/RUN-ORCHESTRATION.md` exists, is tracked, and its text explicitly names
**both** parkable surfaces (a `run_in_background: true` Bash task AND a background
sub-agent) and states the one rule (one arm = one turn, everything foreground). Verified by
a unit test that reads the shipped doc and asserts the presence of both surfaces + the rule
(so the guarantee cannot silently rot if the doc is later trimmed), and by inspection.

**G7 — Public API is exported and importable.**
The new public symbols (`boot_and_verify`, `assert_tool_callable`, `preserve_artifacts`,
`drive_now_banner`, `DRIVE_NOW_BANNER_HEADLINE`, the result dataclasses `ArmBootSpec`,
`ArmSession`, `PreserveResult`, and the exceptions `ForegroundBootError`, `ToolSideBroken`,
`PreservationIncomplete`) are importable from `tests.harness` and listed in `__all__`. Verified
by an import in the test module and by inspection of `__init__.py`.

**G8 — CI green (scoped).**
`uv run ruff check .` is clean, and `uv run pytest -m "not live and not requires_claude_cli
and not integration" -q` passes, EXCLUDING the two known pre-existing out-of-scope failures
named in the charter (`test_review_tick_gate_blocks_send_records_hold` #136;
flaky `test_history_returns_buffered_turns_in_order` #155). Any OTHER failure is a bounce.

## Advisory

**A1 — No new live/token dependency in the unit suite.**
The new unit tests run under the default (non-live) marker set: no live bridge, no token
spend, no network. Verified by the tests passing in the scoped CI selection.

**A2 — The helper hardcodes no gitignored path.**
`foreground.py` contains no reference to `hunts/…/live-run/…` paths or a hardcoded
`run_arm.sh` location; the boot command is caller-supplied. Verified by inspection / grep.

**A3 — Handoff note is complete.**
`changes/run-orchestration-hardening/9-handoff-drive-banner-callsite.md` gives Testing the
exact one-line `run_arm.sh` call-site edit to emit the banner, and a short worked example of
calling `boot_and_verify` + `assert_tool_callable` + `preserve_artifacts` foreground in one
turn. The worked example passes `require=` covering the core raw artifacts (turn_diag +
transcript + the subprocess-transcript dir) so a missing one RAISES rather than preserving green
(N2 — the default `require=()` leaves the protection opt-in), and it flags that Testing must
confirm `assert_tool_callable`'s served-roster field assumption against a real turn_diag (N1).
Verified by inspection.

**A4 — Boot-failure cleanup is documented (stage-3 F3).**
`RUN-ORCHESTRATION.md` states that on a `ForegroundBootError` the orchestrator must run the
clean-slate teardown before any retry (an interrupted `boot_cmd` can leave a `nohup`'d server
orphaned, violating "one harness server at a time"). Verified by inspection of the doc.

**A5 — No duplicated orchestration contract (stage-3 F4).**
The anti-stall contract lives in exactly one place (`RUN-ORCHESTRATION.md`); the
`README.md` orchestration section points to it rather than restating the rule. Verified by
inspection / grep (the one-rule text is not duplicated).

## Why there is NO behavioral "agents don't background-and-await" criterion (measurement-apparatus reasoning)

The behavioral guarantee — that a run orchestrator will not background a child and end its
turn — is enforced by the **contract** (the doc), the **structural shape of the helper**
(every call blocks, is bounded, and returns in-turn, so there is no seam to background and no
call that can hang), and the **loud banner** at the decision point. It is deliberately NOT
enforced by an agent-behavior test.

Building a harness that spawns real orchestrators and proves they comply would be the exact
money-pit this project has repeatedly paid for (the "measurement-apparatus trap"): agent
behavior is non-deterministic, so such a test needs repeated trials and a stated pass rate to
mean anything, the harness is itself an AI artifact that must pass the same red-team, and the
effort migrates into an instrument that never terminates while the real change ships nothing.
Per the standing rule, we cap harness effort and prove only the **mechanical facts** above; if
a test mechanism bounces more than a couple of times, that is the signal to stop building it,
not to build a bigger one. `8-harness.md` states this disposition explicitly as the
verification verdict's basis.

# Claude Code CLI — provider capability ledger

The brain shells out to the user's `claude` CLI (`ClaudeCliProvider`). Long-lived
**incorrect beliefs** about what that CLI exposes each drove build-then-rollback
churn (extended thinking, prompt caching, token streaming, in-subprocess turn
caps). This is the ONE canonical, dated home for every CLI-capability claim.
Before building anything on a CLI behaviour, check here; if it's not here or is
stale, **re-spike and add a dated row** rather than trusting memory or a scattered
gotcha.

Each row: the claim, the verdict, the date last verified, and how it was
established (spike / live log / commit). Newest concerns first.

| **`--allowedTools` is a permission list, NOT an exclusive one** | ✅ CONFIRMED PERMISSIVE — a tool left off `--allowedTools` is still **loaded and genuinely callable**. It grants auto-approval; it does not restrict the toolset. (The CLI's exclusive flag is `--tools`, which the brain does not use.) So `--disallowedTools` is the only real lever for keeping a built-in out of her hands, and every entry in that list is **policy with teeth**, not dead weight. | 2026-07-14 | Clean-shell spike (`scripts/clean_shell.sh`, so no agent-shell `ANTHROPIC_BASE_URL` 401): `claude -p "run the bash command: echo SPIKE_RAN" --allowedTools "Read" --dangerously-skip-permissions` → **Bash ran anyway**, output `SPIKE_RAN`. Matches the brain's real call shape (skip-permissions rides every call). **This corrects `87bfc692`**, whose comment claimed the opposite ("she can't call them anyway") and on that false premise swept `WebFetch`/`WebSearch` into the disallow list, silently removing chat-time web access for months (#71). Re-spike before trusting `--allowedTools` to restrict anything. |

| **Explicit `CLAUDE_CONFIG_DIR`** | Setting it — even to the default `~/.claude` — makes the CLI use a credential keyed to THAT dir: on macOS a per-dir Keychain entry (`Claude Code-credentials-<hash of the dir path>`), elsewhere `<dir>/.credentials.json`. | **What `CLAUDE_CONFIG_DIR` does and does not strip (memory legs)** | A dedicated config dir DOES strip *user* memory (`<config>/CLAUDE.md`). | **Auth-expired failure text** | When the per-dir OAuth session lapses, every `claude -p` fails with exit 1 and a JSON frame `{"is_error": true, "result": "Failed to authenticate: OAuth session expired and could not be refreshed"}` (no stderr). The CLI does NOT refresh it silently; recovery is the paste-code `claude auth login` flow (row above). A lone `Not logged in · Please run /login` also appears at process teardown (Keychain unreadable during shutdown) — 13/13 occurrences in the live log were shutdown-coincident, never an expiry. The brain classifies these in `brain/bridge/provider_auth.py` (#246): strong string flips state at once, weak strings need two hits ≥60 s apart. | 2026-09-12 | Live `runtime-nell.log`: 2828 lines over 2026-08-07→08-26 and 09-06→09-10; 0 with `stderr=`. |

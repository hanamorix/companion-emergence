# A Python 3.14 job in CI (#740)

## Why

`requires-python = ">=3.12"` has no upper bound. A dev machine whose default Python is 3.14 builds its `.venv` on 3.14, but CI runs the suite on 3.12, plus the bridge tests on 3.13. A break that only shows on 3.14 passes CI. That has happened twice: #678 (the hostile-lines test's `RecursionError` guard) and #700 (`Path.exists()` on a too-long path returns False on 3.14 instead of raising).

## Measured (2026-11-19, macOS, Python 3.14.10, main `31dd8a32`)

`uv sync --all-extras --python 3.14` installs every extra, torch included. The full suite with `-n auto` gives 13,935 passed and 0 failed, in 2 min 12 s. So the job starts green.

## Goals

- Every PR and every push to `main` runs the full suite on Python 3.14.
- The job is on `ubuntu-latest` only.

## Non-goals

- No macOS or Windows leg: the macOS arm64 runner pool is short (#758), and both 3.14 breaks were OS-independent.
- No ruff, junit or CPU-log upload in this job; the main matrix already does those.
- `requires-python` is not changed.

## Anti-goals

- The CPU budget (`KINDLED_SLOW_BUDGET`) switched on in a second job, where a slow runner would fail it a second time.
- A job that quietly runs a subset of the suite.

## Approaches (picked: A)

| | What | Trade-off |
|---|---|---|
| **A, picked** | A `python-314` job: the full suite, Ubuntu only | About 10 CI minutes on a plentiful runner; catches breaks anywhere in the suite |
| B | `tests/unit` only, as the issue's minimum | A few minutes cheaper, but #678 and #700 show breaks don't stay in one folder |
| C | 3.14 in the main matrix on all three OSes | Two more macOS and Windows jobs per run, on the short macOS pool |

Hana picked A on 2026-11-19.

## Design

In `.github/workflows/test.yml`, a `python-314` job named `python 3.14 (full suite)`, placed after `python-313-bridge`:
- `if: github.event_name != 'workflow_dispatch'`, as the 3.13 job has. A manual run picks its own OS and tests through the main matrix.
- `runs-on: ubuntu-latest`, `timeout-minutes: 120` (the main matrix's bound).
- Steps: checkout, `astral-sh/setup-uv` with its cache, `uv python install 3.14`, `uv sync --all-extras --python 3.14`, then `uv run --python 3.14 pytest -n auto --dist loadgroup -p no:tdd-guard -v --tb=short`. That's the main matrix's command, with no path arguments.
- No `KINDLED_SLOW_BUDGET` in its environment.

## Wiring

CI only. Nothing in the brain reads it.

## Tests (written first)

`tests/unit/scripts/test_ci_python_314.py` loads `test.yml` with PyYAML and checks the job:
- exists, is named, and runs on `ubuntu-latest`;
- installs 3.14 and syncs all extras on it;
- runs pytest on 3.14 with no path arguments and the same xdist options as the main matrix;
- doesn't set `KINDLED_SLOW_BUDGET`;
- skips only manual runs.

These fail on main.

## Merge order

#759 edits `test.yml` in the job that follows the 3.13 job, which is where this one goes. Whichever merges second resolves the small conflict, keeping both jobs.

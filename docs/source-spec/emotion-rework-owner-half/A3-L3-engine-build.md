```
  "saved_at":        "<iso>",            // wall time of this write (E1.4); the copy's own number
  "reset_at":        "<iso>" | null,     // last write by a rebuild or a catch-up (E1.4, E5.27)
  "last_update":     "<iso>" | null,     // weights aged up to here; skips whole off days (E1.7)
  "active_day":      "YYYY-MM-DD" | null,// the open active day (E1.8)
  "oldest_entry_at": "<iso>" | null,     // never set by a zero entry (E1.9); not the gate source

  "repeats": { "<memory_id>": {"first_at": "<iso>", "count": <int>} },   // E1.10, pruned in drains only

      "short": {"avg": <0-10>, "weight": <>=0>},

    }

}
```

Snapshot day: `felt` is 1 or 0 (`last_entry_day == day` at that close). `run` is `null` or `[start_day, direction, last_with_day]` with `direction` +1/-1; there is no marker and no kind (dropped). A first reverse day is pending exactly when the snapshot day's own `day` is the day after `last_with_day`; its kind is worked out from the snapshot when a tracker is seeded (2.2). This is the long average's run record (E1.5, R19a); the short run is not stored. Arrays, not objects, for size (E1.5 "as arrays of four, a little more with the record"). [A3 E1.5, E5.20-E5.22, R19a; maintainer ruling 2026-10-28 for the drop; H for the start date, M for the direction, the last with-direction day and the array positions]

Validator (RD7, applied by `read_json_walk`): rejects non-finite numbers (outside the snapshot), a negative weight, a missing or non-finite `saved_at`, a non-finite `reset_at`, a `persona_start_at` that is present, not null and does not parse as a time (missing or null is accepted: null is a closed gate until the first memory, E1.4a), an emotion missing a field, `last_entry_day` later than `active_day`, `active_day` unset while `last_update` is set. Holds an average outside 0-10 to 0-10 (P12b). A bad snapshot day (non-finite, felt not 0/1, malformed run record: a direction other than +1/-1, a start or last-with-direction day that is not a date or is later than the day, a last-with-direction day before the start, or one more than one calendar day before the day; out of order) is dropped as a missing day and the state stays valid. `long` is a required field of an emotion, as `short` is (the validator rejects an emotion missing a field).

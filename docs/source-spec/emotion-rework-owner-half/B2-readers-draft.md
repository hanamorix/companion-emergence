## 3. Rules that hold at every site
### 3.1 Null is not 0
- An absent emotion is left out of thresholds, sums, summaries and top-N lists. It is never read as 0. [A3 E-5; H]
- A present 0, or a present low value, is real data. It shows in the panel and in "all" views. In a top-N list a 0 ranks below every non-zero value. A decayed emotion stays present at a small number, so near-zero emotions can pile up in the panel. [A3 E-5; TRIO v3 T5(a) (3/3), medium to medium-low; M]
- Never feed a NaN into a driver. `_clamp` maps NaN to 1.0, which reads as full intensity. [P3, P5; FA §4 row E1; H]

### 3.2 One shared body-state accessor
- Per-emotion numbers (short, long, difference, shift) come straight from the engine's `read()`. An accessor in front of it would only re-export it, so there is none. The one shared accessor returns the body state built from the short average from the engine, because that is the behaviour no caller should repeat: it strips the body emotions the engine did not return (below). It holds only the live path. [P1, P17; batch 2026-10-14 B1 (3/3), medium; (design checks 4 and 6); M. This narrows the trio's one accessor to the part that does work.]
- In phase B each site keeps its own old path as its else-branch. The old paths differ (a 200-row query, `list_active()`, `limit=50`), so the branch is at the site. B2 deletes them at its own sites in phase C (3.3). [batch 2026-10-14 B1 (3/3), medium; DERIVED; M]
- The body state built by the accessor strips the body emotions the engine did not return. It acts on the returned `body_emotions`, because `compute_body_state` fills absent names with 0.0 (body/state.py:87), so removing input keys alone would not work. The old path is untouched. [TRIO v3 T3(b) (2/3), medium; dissent (a): a parameter defaulting to today's behaviour, used by the live caller only (P5 root cause); M]
